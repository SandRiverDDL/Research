# Agentic OPD 项目约定

继承父目录的通用研究规则和操作边界；本项目的流程以这里为准。

## 研究什么

研究多轮 Agent / 工具调用中的 OPD：student 自采样轨迹后，teacher 如何提供可靠监督，训练如何改善长程任务表现。重点看状态覆盖、错误前缀、交互深度、teacher 介入、蒸馏损失和总成本。

当前这批论文排除：OPSD / 自蒸馏、多模态、VLA、benchmark 论文。

通用 OPD 资料链接 `../opd/`，纯 RL 方法链接 `../agentic-rl/`，轨迹生成和过滤等数据机制链接 `../agent-data/`。按本项目视角记录，不默认复制或跨项目写文件。已有资料入口：`../opd/synthesis/reading/agentic-opd.md`。

## 怎么做

- 使用 ARIS wiki；停用本项目默认的 `research-codex-workflow` 和 `autoresearch`，除非用户明确重新启用。初始化时生成的队列、卡片模板和检查工具保留，但不再默认维护或运行。
- **有可用、版本一致的原论文 HTML 时，优先读 HTML。** 只有 HTML 不可用、公式或图表缺失／解析有歧义、需要核对版式，或用户明确要求时，才读对应 PDF 部分。不默认下载 PDF、看页面图片或补 PDF 页码；这条优先于 PDF skill 的通用建议。
- 正文依据原论文，事实附章节、公式或图表等出处。区分作者报告、自己的解释和待验证问题；不知道就写不知道。登记了标题和摘要不等于读完论文。
- wiki 页面沿用 ARIS 的格式；入库、去重和索引优先复用已有工具。不为同一论文另做一份阅读卡，也不把临时检查程序扩成每篇必走的流程。
- 脚本检查结构与链接，原文阅读核查内容；只验证本次变更，不把检查报告当作可复用工具或独立复核。
- 先读 `doc/memory/STATE.md` 和 `research-wiki/index.md`，再按任务需要打开论文、研究问题和关系记录。
- 以本目录为工作和输出边界，wiki 放在 `research-wiki/`；即使 Git 根目录是 Research，也不切到根目录写 wiki。不修改链接指向的 ARIS 上游技能。
- 只有用户明确要求时才细化自己的 idea；不因入库自动启动实验或研究循环。

## 文件放哪里

- `research-wiki/`：论文、研究问题、idea 和关系。
- `papers/`：需要保存的原论文 PDF。
- `synthesis/`：按任务需要做的跨论文分析。
- `doc/memory/STATE.md`：当前任务和完成情况。

ARIS 安装与恢复信息见 `README.md`。只补当前任务需要的文件，流程调整不影响其他项目。
