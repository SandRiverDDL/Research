## Rank 1 — C06: Causal Update Grafting Across Objectives

### 一句话 thesis

**OPD 与 off-policy distillation 在参数更新中存在功能可分的成分：前者主要提高已有解的采样效率，后者才携带 capability-boundary expansion。**

### 为什么它还有空间

[On the Geometry of OPD](https://arxiv.org/abs/2606.07082) 已经发现 OPD 更新会快速锁进低维子空间，并验证早期子空间足以支持后续 OPD 性能；但它还没有把 OPD 与 off-policy distillation 的更新成分移植回同一 base，并因果地区分 small-K efficiency 与 newly-solvable/high-K expansion。

因此这不是再画一张 cosine/SVD 图，而是把近期的描述性 geometry 变成一个功能干预问题。

### 最小方法

1. 从同一 base、同一 prompts、同一生成 token 和优化预算分别训练 OPD 与 off-policy distillation。
2. 用多种低秩分解得到 `shared`、`OPD-only`、`off-policy-only` 更新成分。
3. 将等范数成分分别 graft 到未训练的 base 上。
4. 测量 pass@1、held-out decoder-envelope pass@K、newly solved / forgotten problems。
5. 必做随机子空间、符号翻转、layer shuffle、等范数、不同分解方法与多 seed 控制。

### 决定性 pilot

- 模型：同一 1.5B–1.7B base；一个 4B–8B teacher。
- 数据：约 10K 个可验证数学题。
- 训练：matched OPD 与 off-policy 各 2–3 seeds；先只分析 attention/MLP 的 top-rank 成分。
- 预算：约 60–120 A100-hours；3–5 周完整实现，但首个单 seed pilot 可更快。

**继续阈值：** OPD 成分恢复至少 70% 的 pass@1 增益；off-policy-specific 成分恢复至少 70% 的 newly-solvable/high-K 增益；随机、翻转和 shuffle 控制均低于 20%，并跨 seed 复现。

**停止阈值：** graft 效果对分解方法、层选择或范数极敏感，或者所有 matched controls 都能获得相似行为。

### 最大风险

参数 delta 非线性且依赖基底。失败不能自动说明“没有功能模块”；它也可能只是 graft 操作不合法。论文必须把“移植有效性”本身验证扎实，否则 reviewer 会说这是 task-vector artifact。

### 顶会成立条件

不是“发现 OPD delta 低秩”，而是得到一个跨模型、跨数据稳定的功能分解：**sampling efficiency 与 capability acquisition 可被不同更新成分独立操纵。** 这会直接连接 [test-time scaling 的 capability-loss 结果](https://arxiv.org/abs/2608.11829) 与 OPD geometry。

## Rank 2 — C04: Matched-Delta Causal Control

### 一句话 thesis

**teacher-minus-base delta 只有在其来源确实是 reasoning acquisition 时才会向 student 转移新能力；否则 OPD² 主要传递 style 与一般 policy shaping。**

### 最干净的版本

从同一个 teacher base 构造一个 `reasoning × style` 的 2×2 matched-ancestry factorial：

- 无 reasoning update / 无 style update；
- reasoning-only；
- style-only；
- reasoning + style。

四个 descendant 尽量匹配数据量、LoRA rank、update norm 与训练步数；然后用完全相同的 student、prompts、rollout seeds 和 OPD² 配方做 distillation，用 difference-in-differences 分离 student 的 reasoning、style、language 与 capability-boundary 变化。

### 新颖性压力

[Lightning OPD 2.0](https://arxiv.org/abs/2607.28449) 已经表明 teacher-reference disagreement 混有 wording、formatting 和 reasoning-cadence 的 style bias，并通过 residualization 去除它。因此，单纯再说“delta 里有 style”已经不新。

这里剩余的空间是：用 matched intervention 因果检验 **OPD² 的 delta provenance 是否真的等于 acquired reasoning**，并允许负结论。

### 决定性 pilot

- 两套独立 teacher ancestry，避免只在一个 family 上成立；
- 4B 左右 teacher descendants，Qwen3-1.7B student；
- 每条件 50–100 steps；先用 300–1K prompts 筛方向；
- 指标必须同时含 newly solved、sampler-envelope pass@K、style classifier、输出语言和长度。

**继续阈值：** 两套 ancestry 上，reasoning delta 比 style delta 多产生至少 5 个百分点的 newly solved problems；style delta 显著改变风格但 reasoning 增益不超过 1 点。

**停止阈值：** style-only descendant 本身改变 reasoning，或结果不能跨 ancestry 复现。

### 最大风险

“style-only”不是天然可识别的干预；update norm 匹配也不等于功能强度匹配。这个 idea 更像一篇强因果诊断论文，不像一个容易刷 benchmark 的方法论文。

## Rank 3 — C09: Plan-Lattice OPD

### 一句话 thesis

**OPD 学不到新能力的瓶颈不是局部 teacher signal 不够强，而是 student rollout 只访问主导策略；先由 student 产生多个高层 plan，可打开原本未访问但可被 teacher 局部纠正的状态。**

### 方法

每题由当前 student 先生成 4 个互异的一句话 plan，再分别自行完成 trajectory；teacher 只对这些 unchanged student states 做普通 OPD，不产生 plan，也不按 teacher score 选择 plan。

### 必须打赢的 baseline

[Multi-Rollout OPD](https://arxiv.org/abs/2605.12652) 已经利用同一题的多个 student rollouts。C09 只有在下列等预算对比中仍胜出才成立：

- 1 个普通 rollout；
- 4 个普通 rollout；
- 4 个 prompt paraphrases；
- 4 个显式 diversity-constrained student plans。

### 决定性 pilot

- 1.5B student，500 个数学训练 prompts，100 steps；
- 全条件严格匹配 rollout tokens 与 teacher-forward tokens；
- 除 pass@1/pass@64 外，必须报告 newly solved prompts 与可验证 strategy coverage。

**继续阈值：** 相比 4 个普通 rollouts，newly solved 至少提升 20%，strategy coverage 至少提升 25%，并在两个 benchmark 上有至少 2 点 pass@1 增益。

**停止阈值：** plan 只是表面改写，或收益可被普通多采样/改 prompt 完全解释。

### 最大风险

这条最容易做，但也最容易被 reviewer 判成“multi-rollout + planning prompt”。能否定义可信的 strategy coverage，是成败关键。

## Rank 4 — C01: Decoder-Envelope Capability Audit

### 一句话 thesis

**OPD 的部分 large-K capability loss 可能是 decoder-relative 的 probability reshaping，而非正确轨迹从 model support 中消失。**

### 为什么先做它

2026-08-12 的 [test-time-scaling OPD 论文](https://arxiv.org/abs/2608.11829) 用 pass@K 得出 OPD 更像提高 sampling efficiency、且忘掉的问题多于新学会的问题。C01 直接检验这个新结论是否依赖固定 decoder。

### 实验

- 两组公开 base/OPD checkpoint pairs；
- held-out validation 上预注册 temperature/top-p/min-p grid 或 mixture；
- test 上给每个 checkpoint 完全相同的 generated-token budget；
- 同时报 fixed decoder 与 envelope 下的 learned / retained / forgotten sets；
- 避免在 test set 对每题或每模型事后挑最优 decoder。

**继续阈值：** 两组模型上，envelope 至少减少 35% 的 forgotten set，并消除或反转 base 的 pass@64 优势。

**停止阈值：** gap 在 held-out decoder envelope 下基本不变。

### 价值边界

这是最便宜、最值得先跑的 probe，但单独一张 decoder sweep 不够顶会。只有它显著改写 capability-loss 结论，或进一步导出可预测的 decoder–model scaling law，才可能成为主论文。

## 推荐执行顺序

1. **先跑 C01。** 它只需 inference，能最快判断最新的 capability-loss 叙事是否有评估漏洞。
2. **若要押一个完整项目，押 C06。** 先做一个模型、一个 seed、top-rank graft 的合法性检查；随机与 layer-shuffle control 过不了就立刻停。
3. **C09 是 fallback。** 只有在四组等预算 baseline 上出现 strategy-coverage 的明显差异才继续。
4. **C04 只在能构造两套可信 matched ancestry 时做。** 否则 causal claim 不可识别。
