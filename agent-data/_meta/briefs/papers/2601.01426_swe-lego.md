# Brief: SWE-Lego

Source: arXiv HTML / abstract page, arXiv:2601.01426v2, submitted 2026-01-04, revised 2026-01-07.

## Bounded Source Notes

- Position: SFT-only recipe for software issue resolving, contrasting with heavier mid-training / SFT / RL combinations.
- Dataset: 32k high-quality executable task instances and 18k validated expert trajectories from mixed real-world PR tasks and synthetic bug-injection tasks.
- Data construction: selects 3,000+ permissively licensed, actively maintained Python repositories, builds Docker sandboxes, and keeps repositories that build and pass sanity tests.
- Real/synthetic complementarity: real PR data supplies complex production bugs; synthetic bug injection supplies scalable focused tasks. Scaling synthetic instances per repository improves valid trajectories and SWE-bench Verified resolve rate.
- Training mechanism: refined SFT uses step-level error masking and difficulty curriculum; reported SWE-Lego-Qwen3-8B 42.2% and Qwen3-32B 52.6% on SWE-bench Verified, with verifier-based TTS further improving results.
- Data hygiene: paper/project emphasize hack-free evaluation and include Git-hacking examples.

## Project Use

Treat as a core seed for partial-supervision trajectory curation: do not discard whole long trajectories when only local steps are bad; pair this with executable sandbox validation and curriculum over interaction length.
